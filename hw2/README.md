## Воспроизведение

Проверено с Python 3.13.5. Создать чистое окружение и установить ровно две зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
chmod +x solution.py
./solution.py --submission_file=submission.csv PATH-TO-DATA
```

В PATH-TO-DATA должны находиться шесть исходных файлов соревнования ДЗ2.
`requirements.txt` получен командой `pip freeze` из отдельного окружения.

Скрипт заново рассчитывает статистики корпуса, подбирает коэффициенты только по
обучающим запросам и создаёт CSV `ObjectId,Score` в исходном порядке `objects.csv`.
Скоры сравниваются только внутри одного запроса. Дополнительно сохраняется
`submission.report.json` с параметрами и результатами всех вариантов.
При равных скорах тестовые кандидаты упорядочиваются по ObjectId.

Опциональный повторный запуск со статистиками из локального кеша:

```bash
./solution.py --submission_file=submission.csv --cache_dir=.cache PATH-TO-DATA
```

Кеш не нужен для проверки решения. Его ключ включает SHA-256 кода и всех входных
файлов. Кеш не входит в архив. Метки и подбор параметров обрабатываются заново.

## Метод

Используются только файлы соревнования и классические текстовые модели.
Ранжирующие формулы реализованы вручную на NumPy.

Предобработка: нижний регистр, ё → е, токены из не менее двух букв/цифр/символов
подчёркивания, русский Snowball-стемминг. Для контрольного TF-IDF используются
нестеммированные токены с такой же токенизацией. Стоп-слова не удаляются.
URL декодируется из percent-encoding и используется только как текстовая зона.
Никаких запросов к сайтам документов скрипт не делает.

Основной скор — BM25F:

```
IDF(t) = ln(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
TW(t,d) = tf_body / (1-b_body+b_body*len_body/avg_body)
        + w_title*tf_title / (1-b_title+b_title*len_title/avg_title)
BM25F(q,d) = sum_t qtf(t)*IDF(t)*(k1+1)*TW(t,d)/(k1+TW(t,d))
```

DF считается по объединению заголовка и текста, документ учитывается один раз.
Длины и средние длины рассчитываются по всем токенам, а не только словам запроса.
Выбранные параметры: k1=2.0,
b_body=0.5, b_title=0.3,
w_title=8.0.

Сетка: k1 ∈ {0.6, 1.2, 2.0}, b_body ∈ {0.2, 0.5, 0.8},
w_title ∈ {1, 3, 8}, b_title=0.3. Всего 27 вариантов.

Для смешивания каждый скор нормируется min-max внутри запроса. Постоянный
скор превращается в нули. Итоговая формула:

```
Score = norm(BM25F)
      + 0.20 * norm(TFIDF_cosine)
      + 0.05 * norm(title_bigram_fraction)
      + 0.05 * norm(body_bigram_fraction)
      + 0.05 * norm(URL_query_term_coverage)
```

Биграммный скор — доля различных соседних пар стемов запроса, которые есть в
соответствующей зоне. URL coverage — доля различных стемов запроса в URL.
Дополнительно проверялись BM25 по заголовку и тексту, LM Дирихле (μ=2000),
IDF-взвешенное покрытие заголовка. Их веса выбраны равными нулю.

Веса перебираются координатным спуском по дискретной сетке
{0, 0.05, 0.1, 0.2, 0.4, 0.8}, два прохода, вес BM25F фиксирован равным 1.
Это подбор нескольких коэффициентов формулы по разрешённой в условии схеме.

## Оценка и подбор параметров

Из 1 000 размеченных запросов 800 используются для подбора, 200 — как holdout.
Разбиение по запросам, seed=42. Сначала выбирается BM25F на 800 запросах,
затем на них же подбираются веса комбинации. Holdout используется один раз
для выбора между готовой комбинацией и выбранным BM25F. Поэтому holdout
не является совершенно независимой итоговой оценкой после этого выбора.
Тестовые метки и публичный лидерборд в подборе не участвуют.

Метрика в точности использует gain=2^Label−1, discount=1/log2(rank+1), K=10.
При IDCG=0 результат запроса равен нулю.

| Вариант | Подбор, 800 запросов | Holdout, 200 запросов | Все 1 000 |
|---|---:|---:|---:|
| Контрольный TF-IDF | 0.612378 | 0.588527 | 0.607608 |
| BM25F | 0.623268 | 0.602747 | 0.619164 |
| BM25_body | 0.617685 | 0.600411 | 0.614230 |
| BM25_title | 0.615107 | 0.590583 | 0.610202 |
| LM_Dirichlet | 0.612900 | 0.599564 | 0.610233 |
| Итоговая комбинация | 0.626997 | 0.607116 | 0.623021 |

Контрольный TF-IDF — собственное воспроизведение семейства бейзлайна, а не
утверждение о побитовом совпадении с закрытым кодом Kaggle. Используются
обычный TF, сглаженный IDF и косинус по Title+Body. Норма документа учитывает
весь словарь корпуса. Отличия предобработки могут менять результат.

Парный прирост на holdout относительно контрольного TF-IDF:
0.018588; приближённый 95% интервал по позапросным разностям:
[0.002654, 0.034523].
Это описательная оценка без поправки на выбор итоговой формулы.
Локальные метрики не заменяют проверку публичного скора Kaggle.

## Производительность и проверки

В корпусе 74,848 документов. Полный запуск без кеша на этой машине
занял 211.2 с. В CSV 50,353 строк.
Время на Linux зависит от процессора и диска; отдельно на Linux не измерялось.

Текст корпуса читается потоком дважды. В памяти остаются DF полного словаря
для контрольного косинуса и массивы частот только слов запросов. Полные страницы
и полный координатный индекс не сохраняются. Пиковая RAM отдельно не измерялась.

Проверено: BM25F и LM совпадают со скалярными формулами на небольшом корпусе;
TF-IDF совпадает с независимым полным косинусом; метрика корректна на идеальном
и обратном ранжировании; итоговые ObjectId совпадают с `objects.csv`, все скоры
конечны. Проверка воспроизводимости — повторный запуск с теми же данными.
